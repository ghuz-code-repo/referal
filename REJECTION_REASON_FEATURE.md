# Отчет: Добавление обязательного комментария при отказе в выплате

**Дата:** 20 октября 2025  
**Статус:** ✅ Реализовано и протестировано

---

## 📋 Проблема

При смене статуса договора на "Отказано" (status_id = 500) не требовалось указывать причину отказа. Это приводило к отсутствию документации о причинах отклонения выплат.

---

## ✅ Реализованное решение

### 1. Добавление поля в базу данных

**Миграция:** `migrations/add_rejection_reason_to_deal.py`

Добавлена колонка `rejection_reason` в таблицу `referal_deal`:

```sql
ALTER TABLE referal_deal
ADD COLUMN rejection_reason TEXT
```

**Структура поля:**
- Тип: `TEXT`
- Nullable: `True` (NULL для всех статусов кроме 500)
- Назначение: Хранение причины отказа

### 2. Обновление модели данных

**Файл:** `models.py`

```python
class ReferalDeal(db.Model):
    # ... существующие поля ...
    
    rejection_reason = db.Column(db.Text, nullable=True)
    # Причина отказа (обязательно при status_id = 500)
```

### 3. Серверная валидация

**Файл:** `routes/admin_routes.py`

Функция `update_deal_status()` обновлена для проверки наличия комментария:

```python
@admin_bp.route('/admin/deal/<int:deal_id>/update_status', methods=['POST'])
def update_deal_status(deal_id):
    # Получаем данные
    new_status_id = data.get('status_id')
    rejection_reason = data.get('rejection_reason', '').strip()
    
    # ✅ ВАЛИДАЦИЯ: Проверяем обязательность комментария при отказе
    if new_status_id == 500 and not rejection_reason:
        return jsonify({
            'success': False,
            'message': 'При отказе необходимо указать причину в поле "Комментарий об отказе"'
        }), 400
    
    # Сохраняем или очищаем причину отказа
    if new_status_id == 500:
        referal_deal.rejection_reason = rejection_reason
    else:
        referal_deal.rejection_reason = None  # Очищаем при смене на другой статус
```

**Логика работы:**
1. При выборе статуса 500 (Отказано) - проверяется наличие `rejection_reason`
2. Если комментарий пустой - возвращается ошибка 400
3. При смене на другой статус - поле `rejection_reason` очищается

### 4. Клиентская часть (Frontend)

**Файл:** `templates/admin.html`

#### 4.1. Интерактивный запрос комментария

```javascript
select.addEventListener('change', function() {
    const newStatusId = parseInt(this.value);
    
    // ✅ Если выбран статус "Отказано" (500), запрашиваем комментарий
    if (newStatusId === 500) {
        const rejectionReason = prompt('Укажите причину отказа (обязательно):');
        
        // Проверка на пустой комментарий
        if (!rejectionReason || rejectionReason.trim() === '') {
            alert('Для отказа необходимо указать причину');
            this.value = currentStatus; // Возвращаем текущий статус
            return;
        }
        
        // Отправляем запрос с причиной отказа
        updateDealStatus.call(this, dealId, newStatusId, currentStatus, rejectionReason.trim());
    } else {
        // Для других статусов - обычное подтверждение
        updateDealStatus.call(this, dealId, newStatusId, currentStatus, null);
    }
});
```

## 🔄 Алгоритм работы

### Сценарий 1: Отказ в выплате

1. Администратор выбирает статус "Отказано" (500) из dropdown
2. Появляется prompt с запросом причины отказа
3. Администратор вводит причину (например: "Недостающие документы")
4. Если поле пустое:
   - ❌ Показывается alert: "Для отказа необходимо указать причину"
   - ✅ Статус не изменяется
5. Если причина введена:
   - ✅ Отправляется запрос на сервер с `rejection_reason`
   - ✅ Сервер валидирует и сохраняет
   - ✅ Причина отображается под dropdown в виде желтого блока

### Сценарий 2: Смена статуса с "Отказано" на другой

1. Администратор выбирает любой другой статус (например, "Готов к выплате")
2. Подтверждает изменение
3. Отправляется запрос на сервер без `rejection_reason`
4. Сервер автоматически очищает поле `rejection_reason` (устанавливает NULL)
5. Желтый блок с причиной отказа исчезает

### Сценарий 3: Смена между обычными статусами

1. Администратор выбирает любой статус кроме 500
2. Подтверждает изменение
3. Отправляется запрос без `rejection_reason`
4. Статус обновляется без требования комментария
